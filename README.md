# Генератор сетевых конфигураций Linux (ifupdown)

Генерирует отдельный `/etc/network/interfaces` для каждого хоста и список таблиц маршрутизации `tabel<VLAN>` из CSV. Используется Python 3.9+ без сторонних библиотек. Генератор **не изменяет сеть** и не записывает ничего в `/etc`.

**Все данные этого репозитория синтетические.** Три сервера `demo-alpha`, `demo-beta`, `demo-gamma`, все IPv4-адреса, шлюзы, VLAN, bond, имена портов и описания придуманы для демонстрации. Адреса принадлежат специальным блокам документации [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737): `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`. Они **не предназначены для действующей сети**. Для развёртывания замените образцы своей адресацией и проверьте конфигурацию сетевого оборудования.

## Входные CSV

Обязательных файла два: `bonds.csv` и `networks.csv`. Необязательный `extra_interfaces.csv` можно **удалить полностью**, если дополнительных физических интерфейсов нет.

### `bonds.csv`

```csv
host,bond,slaves,mtu
demo-alpha,bond7,enp5s0f0 enp5s0f1,9000
demo-alpha,bond8,enp6s0f0 enp6s0f1,1500
```

- `host` — произвольное название узла (это же название выходного файла). Допустимы буквы, числа, пробелы и Unicode, но не символы пути `/` и `\`.
- `bond` — имя агрегата; должно начинаться с `bond`.
- `slaves` — два или больше разных физических интерфейса через пробел.
- `mtu` — MTU bond и его физических интерфейсов.
- Режим агрегирования: `802.3ad` (LACP), `miimon=100`, `updelay=200`, `downdelay=200`, `xmit-hash-policy=layer3+4`. Линки и LACP-группа должны быть настроены на коммутаторе.

### `networks.csv`

```csv
host,bond,vlan,ip,mask,gateway,mtu,tagging,default_route,description
demo-alpha,bond7,171,192.0.2.2,255.255.255.248,192.0.2.1,1500,tagged,yes,Sample access network
demo-alpha,bond7,272,198.51.100.66,255.255.255.248,198.51.100.65,9000,tagged,no,Sample data network
demo-alpha,bond8,373,203.0.113.130,255.255.255.248,203.0.113.129,1500,untagged,no,Sample native network
```

- `host` — совпадает с `host` в `bonds.csv`; отдельного `hosts.csv` **нет**.
- `bond` — bond, на котором расположен VLAN.
- `vlan` — номер 1–4094; создаётся мост `br<VLAN>`.
- `ip` — IPv4-адрес; допускается запись с CIDR (например, `192.0.2.2/29`).
- `mask` — десятичная маска, префикс или `/префикс`; при CIDR можно оставить пустой. Если оба указаны, должны совпадать.
- `gateway` — шлюз этой сети, в пределах её подсети.
- `mtu` — MTU VLAN-интерфейса и моста; пустое значение наследует MTU bond. Не может превышать MTU bond.
- `tagging` — `tagged` или `untagged`. При `tagged` создаётся `bondX.VLAN`; при `untagged` мост подключается непосредственно к bond. На один bond допускается только один untagged VLAN. MTU untagged-моста совпадает с MTU bond.
- `default_route` — `yes` или `no`: **ровно одна** сеть на каждом сервере отмечается `yes`. Только через неё создаётся основной `default` в таблице `main`.
- `description` — необязательный комментарий в конфигурации.

Для **каждой** сети независимо от `default_route` формируются: маршрут в свою подсеть через bridge, маршрут через шлюз в индивидуальной таблице и `ip rule` по исходному адресу. Названия таблиц — `tabel171`, `tabel272` и т. д.; ID в `rt_tables.additions` по умолчанию начинаются с 100. `pre-down` удаляет правила и маршруты при штатном отключении интерфейса.

### `extra_interfaces.csv` (необязателен)

```csv
host,interface,mtu
demo-gamma,enp8s0,1500
```

Позволяет дополнительно поднять физические интерфейсы как `inet manual`, не включая их в bond. Если не нужен — удалите файл; генерация продолжит работать.

## Запуск

```bash
python3 --version
chmod +x generate.sh
./generate.sh
```

Результат находится в каталоге `generated/`: один файл на каждый `host`, `rt_tables.additions` и `validation.txt`. Название файла равно `host` без расширения.

Другой каталог вывода и перезапись:

```bash
./generate.sh ./example-output
./generate.sh ./example-output --force
```

Прямой вызов Python:

```bash
python3 generate_interfaces.py --input . --output ./example-output --table-start 100
```

## Тесты

```bash
python3 test_generator.py
```

Проверяются генерация, адресация, MTU, tagged/untagged, отдельные таблицы, маршрут по умолчанию, свободные имена хостов, наличие/отсутствие необязательного файла и некорректные входные данные. Тестовый набор состоит из **3 вымышленных хостов, 4 VLAN и 12 IPv4-назначений**.

## Перед применением на реальном сервере

Содержимое `rt_tables.additions` — **пример записей**, а не автоматически применяемое изменение системы. Сначала проверьте доступность ID таблиц в `/etc/iproute2/rt_tables`, корректность масок и IP, физические имена портов, LACP, назначение VLAN на коммутаторах, MTU на всём пути и настройки `rp_filter`. Установка и перезапуск сети могут оборвать текущий SSH-сеанс; используйте консоль.

## Безопасная публикация и работа со своими данными

- Публикуйте только исходники и **синтетические демонстрационные CSV** из этого архива.
- Реальные CSV и сгенерированные конфиги храните в отдельном непубликуемом каталоге, например `private/`, и вызывайте генератор с `--input` / `--output` на этот каталог.
- Не коммитьте локальные архивы, резервные копии, экспорты Excel, логи и результаты генерации по реальной инфраструктуре. `.gitignore` исключает наиболее типичные такие файлы, но **не гарантирует защиту от публикации**: всегда проверяйте `git status`, `git diff --cached` и историю Git.
- Если реальные данные уже попадали в историю публичного репозитория, создание этого чистого архива не удалит их оттуда. Публикуйте как новый репозиторий без импорта прежней истории.

В архиве **нет** исходной частной адресации, старых конфигураций, персональных имён, внутренних адресов, реальных имён портов или данных из чужого окружения.
